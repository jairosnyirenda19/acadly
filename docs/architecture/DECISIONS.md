# Decisions

Append-only log. A decision is changed by adding a new entry that supersedes the old one. Status: **Accepted**, **Proposed** (needs the product owner), **Superseded by D-xxx**.

| D-017 | 2026-11-14 | Design system is in-house on Radix primitives and Tailwind tokens | Accepted | Total design control with accessible foundations |

| D-025 | 2026-11-14 | Search everything follows the eOffice seam: one `SearchSource` per module registered from its manifest, closed groups absent, hits built by hand, hidden fields never matched, the typed text never stored, trigram indexes, per-source time limit. | D-030 | 2026-11-14 | **One deployment per school.** Each school has its own application, database, storage and address. | D-031 | 2026-11-14 | Two database roles are kept: `acadly_owner` runs migrations; `acadly_app` runs the application and cannot change the schema. History tables are append-only by privilege and by trigger | Accepted | Protects a school's own records, which D-030 does not replace |
| D-032 | 2026-11-14 | The Acadly IQ-X mark: a thin-line sheet that carries a graduation cap, behind a solid closed book with a ribbon marker, a cut-out `a` from Archivo ExtraBold, and a quiet IQ-X. | D-033 | 2026-11-15 | The web apps sign in with a session cookie through Laravel Sanctum (stateful). The CSRF cookie route is `/api/v1/auth/csrf-cookie`, so the apps reach the API through one path. Passwords: at least 12 characters. Five failed sign-ins for one address and one IP lock that pair for a minute. One message for every sign-in failure | Accepted | No tokens in browser storage; no account enumeration |
| D-034 | 2026-11-15 | Both PostgreSQL connections run with `timezone = UTC`. The application writes UTC; a session in the server's local zone shifted every stored time and made new reset links appear expired | Accepted | Found by the password reset test; guarded by a test |
| D-035 | 2026-11-15 | Access is the kernel's own scoped RBAC: permissions are enum cases declared in module manifests; `access_permissions` mirrors them through `acadly:sync`; roles hold permissions; assignments hold a role at a scope for a period. The system role `administrator` holds every permission. The first administrator is created once with `acadly:administrator`. Nobody can give a role whose permissions they do not hold at that scope; the last institution-wide administrator cannot be removed | Accepted | Implements 03 §5 |
| D-036 | 2026-11-15 | Until the notification catalogue is built, the password reset email uses Laravel's mail notification with Acadly's own wording. It moves to the catalogue as topic `account.password_reset` when Notify is built | Accepted (temporary) | Sign-in had to work before Notify exists |
| D-037 | 2026-11-15 | The sign-in screens show the school's name from `GET /api/v1/school` (public; returns the name only). Until the institution record exists, the name comes from `ACADLY_SCHOOL_NAME`. The web apps move between screens with a small kernel router (`navigate`, `useLocation`); a routing library is chosen when the console has real navigation | Accepted | One deployment per school (D-030) |
| D-038 | 2026-11-16 | The audit trail is built in the kernel (`Acadly\Kernel\Audit`). Audit actions are enum cases declared like permissions (`Module::auditActions()`); the kernel owns `identity.*`, `access.*` and `audit.*`. A line is written in the caller's transaction under a transaction-level advisory lock, with a gapless `seq` and `hash = sha256(prev_hash ‖ canonical(line))`. `Access::check()` writes every refusal. An architecture test fails on an Action that neither writes a line nor carries `#[NotAudited]` | Accepted | Implements 10 §3–5, §7 |
| D-039 | 2026-11-16 | Departures from 10 §3 while the trail is young: `audit_events` is not partitioned yet (partition by month when volume needs it); the person a line concerns is `about_person_id`, because the kernel names no domain; the session is stored as a fingerprint (`session_ref`), never the id; actor kind `anonymous` covers requests with no account; the app sends `X-Acadly-Channel` (`console`, `portal`), anything else is `api`, and scheduled work is `job` | Accepted | Rule A2; a session id is a credential |
| D-040 | 2026-11-16 | `audit:seal` runs nightly at 01:00: it verifies the whole chain, then signs the head (HMAC-SHA256 with the deployment key) into `audit_seals` and a copy in private storage (`audit-seals/`). A trail that does not verify is not sealed; the failure is written to the trail as `audit.chain_broken` and logged as critical. The retention-locked object store and the `system.audit_tampered` notice arrive with Files and Notify | Accepted (partial) | Implements 10 §5 |
| D-041 | 2026-11-16 | Domain events: an event class implements `DomainEvent` (stable `eventName()`, scalar payload). Modules declare `events()` and `subscriptions()` in the manifest; the kernel publishes `access.role_assigned` and `access.role_ended`. `Outbox::record()` refuses to run outside a transaction. After commit a unique `PublishOutbox` job claims waiting rows with `FOR UPDATE SKIP LOCKED` and queues one `DeliverEvent` per consumer; `events:publish` runs every minute as a safety net. A delivery writes `consumed_events (consumer, event_id)` in the same transaction as the consumer's work, so each consumer sees each event at most once and a failure is retried (8 attempts, backoff up to an hour) | Accepted | Implements D-013 and 05 §5 |
| D-042 | 2026-11-16 | Module activation is `ModuleActivation::state()`: installed, then offered (the `ModuleOffering` socket, bound to `OfferEverything` until Profile Blueprints exist), then licensed, then switched on. Core domains and the kernel areas are always on; optional modules are off until the school switches them on. Switches are append-only rows in `module_switches` with who and why, made by `SwitchModule` (permission `modules.manage`, reason required, audited, event `modules.switched`). `Access::check()` refuses a permission whose module is off with `module_inactive`; module routes carry `module:<key>`. Switching is per deployment for now; per division arrives with divisions | Accepted | Implements 01 §6 and rule D7 |
| D-043 | 2026-11-16 | The licence is a JSON document signed by IQ-X with Ed25519 (libsodium). The deployment holds only the public key, `ACADLY_LICENCE_PUBLIC_KEY`, and installs licences with `acadly:licence <file>` into append-only `system_licences`; the newest that verifies is in force. Expired: reading and exporting go on, changes answer `licence_read_only`. No verified licence: optional modules are off. A development or test machine with no key configured runs a development licence that includes every module | Accepted | Implements 03 §5.5; the licence cannot be edited into a larger one |
| D-044 | 2026-11-16 | `GET /api/v1/me/context` returns the account, the school, the licence state, the modules that are on, divisions, campuses, vocabulary, navigation and grants. Divisions, campuses, vocabulary and navigation are empty lists until their stages. The web kernel exposes `ContextProvider`, `useCan()`, `useModule()` and `useSchool()`; `can()` also requires the permission's module to be on | Accepted | Implements 03 §5.8 and 06 §4 |
